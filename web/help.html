Help & limitations

Portable Windows app and game languages

Open RF4S Save Editor.exe on Windows 10/11 x64. Python, Qt and the browser engine are bundled; no Python, Node, WebView or other installation is needed. First launch extracts the bundled runtime into a temporary folder. Use Read game folder in the native toolbar to read definitions, recipes and localized names from your installation without modifying it.

Game names offers English, Japanese, French, German, Korean, Traditional Chinese and Simplified Chinese when available in your game. This translates item, recipe-result, character and skill names, not editor instructions. Missing names fall back to English. The selected language is saved as a preference, never written into your save. In the source browser version, import extracted rf3TxtItem_split2_1.*, rf3TxtNpc_split2_1.* and rf3TxtSkill_split2_1.* through Overview. Description tables ending in _split2_2 are not accepted as names.

Attached items and elements

Enable item editing, select equipment in Bag & storage and expand Attached items & element. You can edit inherited equipment abilities, three crafting attachments, nine upgrade attachments and the total-level / rarity bonuses. Blank preserves the existing value; 0 removes it. These fields store 10-bit item IDs, so IDs above 1023 cannot be attached. Stacked items use a different representation and do not expose these controls.

Element selection applies to weapons/tools. It appends the required crystal(s) after existing upgrades, never deletes existing attachments, and raises item level to include the new upgrades. Different elements may need two crystals because the first clears a conflicting element. Full equipment is refused rather than silently losing an upgrade. Armor elemental resistances are not exposed as a guessed saved element field. Special item interactions and full bonus recalculation remain the game's responsibility. Test exported copies in-game with backups.

Marriage flag management

The Marriage section groups spouse, anniversary, ring acceptance, wedding memory and candidate event records with readable controls. Enable it explicitly, select a candidate for the two event flags, review your draft and apply as one undoable edit. Selecting an event candidate does not automatically change the spouse. Unknown stored spouse IDs remain visible and untouched until explicitly replaced.

This is not a complete marry/divorce operation. It does not play proposal or wedding events, initialize children/pregnancy, recalculate friendship, change schedules or update system wedding unlocks. Use the separate System save controls for rf4_sys.sav. Unapplied marriage drafts block export even when editing is disabled.

Supported saves

PC / Steam slots are 140,424 bytes; the supplied extracted Switch slots are 140,416 bytes. System files rf4_sys.sav are 9,304 bytes and begin with RF4D. Other sizes, encrypted containers and other console formats are rejected. Size and a matching slot checksum alone do not authenticate the file.

A safe workflow

  1. Close the game and back up your complete save folder.
  2. Open a slot save and check its date and checksum.
  3. Apply your changes, then review the exact changed bytes.
  4. Download the byte-exact original backup and export the edited save.
  5. With the game closed, manually replace the intended slot using its original rf4_sNN.sav filename.

The editor never overwrites a save or game file. It cannot verify download completion or manage Steam Cloud conflicts. Unsaved edits live only in memory and disappear when the page closes or reloads.

The main interface

Only applicable controls are shown for the loaded file. Slots show player values, bag / storage, skills, recipes, friendship, people, existing monsters, trophy records and export. New editors start collapsed and require explicit opt-in. System saves show persistent unlocks and export. Expert tools contains story / subquests, references and raw edits. Closing any editor keeps pending drafts, which still block export. Expand Byte changes and checksum to inspect working-byte edits and the export CRC.

Skills, recipes and actors

Skills expose level and XP independently. Crafting skills / resistances cap at 99; others at 999. Direct levels do not award level-up stat gains. Recipes store only learned flags, not their recommended difficulty. Read extracted rf3Recipe*.bin definitions, or generate personal recipe references with scripts/gather_save_references.py and a supplied game-folder argument. Linked variants share their learned state; bulk actions affect only filtered recipes.

Friendship supports 23 main characters plus Barrett / Raven, with point conversions and guest packed bits preserved. It does not trigger dating, marriage, gifts, story events or Steam achievements. People / existing tamed monsters expose stored combat level, XP, health, rune points and base attributes. Derived stats are not recalculated; monster names, species, barns and chores remain unchanged. No actor spawning, monster creation, taming, species replacement or renaming is provided.

Choose Bag, Fridge, Storage, Weapon box or Armor box in Bag & storage → Container. Fridge / storage serialize 990 records each; weapon / armor boxes 120 each. Filling a later slot does not unlock capacity. The same item-definition, metadata, stack and level rules apply.

Trophy records exposes 25 verified recorded achievement / festival fields, not every trophy-room entry or physical trophy items. Festival ranks are none, first / gold, second / silver and third / bronze. These edits do not unlock Steam achievements. New fields pass in-memory byte / CRC checks; in-game acceptance remains pending. Keep backups.

Verified fields and unknown layouts

The upstream parser verifies calendar and GameFlags layouts. The supplied executable and real saves corroborate additional stored fields; these do not use the community 3DS map. Layout verification is not universal semantic acceptance. Equipped-position labels, farming, complete trophy-room ownership and the state needed to safely create actors or rewrite relationships remain incomplete. Date edits do not simulate daily game updates. Evidence is recorded in docs/save-layout.md and docs/extended-layout.md.

Player values

Money and order points → Order points edits prince/princess points, the currency spent on orders. It is signed 32-bit at 0x20710, with the executable's range of 0–99,999. Apply the player draft to write it in memory; undo restores the previous bytes. This does not unlock orders or change their system flags.

Money is signed 32-bit at 0x4C, bounded by the executable to 0–2,000,000,000. Lumber / material stone / fertilizer are signed 32-bit at 0x3C, 0x40, 0x44, bounded to 0–50,000 by their addition routines. Maximum / current health are signed 32-bit at 0x54 / 0x58; maximum / current rune points are unsigned 16-bit at 0x5C / 0x5E. Strength, intelligence and vitality occupy the low 24 bits at 0x60, 0x64, 0x68; their upper bytes are preserved.

These are base values, not equipment-adjusted attack / defense. Health / rune / attribute maxima shown are storage limits, not verified gameplay caps. Use reasonable values: extreme numbers may overflow derived calculations or be clamped in-game. Current health and rune points must not exceed their maxima; zero current values are allowed. Minimum base attributes of 1 and nonzero maxima are conservative editor checks. Changing equipment level does not recalculate its saved bonuses.

Named player and bag sections are hidden if the original player profile fails these checks. Calendar / expert features can still handle such files; a plausible profile is not proof of a genuine save. Raw edits that invalidate an originally recognized player profile block export until corrected or undone. Apply or clear player drafts before exporting.

Bag editing

The saved bag contains 60 records of 28 bytes, starting at 0x5BD8 and ending before 0x6268. Held / equipped entries and the following spell table are excluded. Occupied slots appear by category by default. All 60 positions are available in the saved-slot selector and all-slots view; filling a later slot does not unlock bag capacity.

Load item definitions in Expert tools → Item reference if they are not already available, and enable bag editing. Choose a saved slot, then an item group and item. Browsing works without a search; name / ID search narrows the selected group. Categories come from definitions, not guessed names. To add an item, select an empty saved slot; the card view switches to all slots. Manual IDs are under Manual item ID.

Set quantity and apply. Stackable items allow up to 9 units; other items allow 1. Category placeholders are rejected. Choose Empty slot / remove item, or use ID 0 with quantity 0, to clear a slot. Apply or clear drafts before switching slots or exporting; draft values are never silently exported.

For the same ID, quantity and level edits preserve unknown packed flags, upgrades and other metadata. Leave level blank to preserve individual unit levels, including mixed-level stacks. Added units inherit the first existing level. Entering 1–10 sets all level entries. A replacement ID creates a fresh record and clears upgrades / other saved metadata; a blank replacement level starts at 1. Clearing a slot also clears its whole record. Undo restores the exact previous bytes.

Inventory insertion does not update shipping history, item discovery, recipes, unlocks or equipped positions. Some item IDs may not behave as normal bag items even when their definitions exist. Test exported copies with backups.

Gender on export

Under Review & export → Character gender, enable Auto-correct gender on export. Choose Match original save, Male · Lest or Female · Frey. Correction is off by default. The verified byte at 0x36 is 0 for male and 1 for female; matching the original uses the frozen loaded byte, even after a raw gender edit. An unrecognized original requires an explicit male or female choice.

Reset appearance, portrait and outfit is separate and unchecked by default. It clears the appearance-swap bit at 0x38, outfit bits 18–23 at 0x74, and the signed persistent appearance selector at 0x20740, preserving neighboring bits and the following word. This removes those cosmetic choices. Keep it off to preserve your swapped appearance / outfit; gender alone may not change swapped visuals. Names are never renamed.

These options affect only the exported copy and CRC, not the working bytes, original backup or undo history. They also apply before experimental PC / Switch conversion. The JSON report records original / edited / exported cosmetic state separately from working-byte changes.

The initial reset missed 0x20740. A supplied male save had 9,999 there, causing the executable's load branch to select Frey visuals while retaining male dialogue state. The corrected output selects matching body / portrait resources in a read-only executable replay; it has not yet been accepted in-game. Reload the editor to get the fix, export with reset checked, close the game fully, and test the corrected copy after backing up your save folder.

Story jumps and subquests

The editor loads 1,822 developer symbols and nonconflicting CT labels automatically. Use group filters or search QUEST / SUBEV. You can optionally replace developer symbols with an extracted emdeb.bin. Main story is bits 0–8, values 0–511; register values are assembled most-significant first, while physical bits inside each byte use least-significant-first addressing. The v13 CT's three-bit Story Progress entry is rejected. CT labels are interpretations, not proof of complete semantics.

  1. Back up the entire save folder and close the game. Open the slot and enable flag editing.
  2. Acknowledge incomplete dependencies, choose the numeric target or a script witness, and read the jump preview. Witnesses are not presets.
  3. Optionally read a named profile or checksum-valid donor snapshot. Check Include the staged named-flag profile in this jump to combine it with the target. If the profile contains a main-story value, it must agree with that target.
  4. A decrease additionally requires Explicitly allow rewind. The standalone profile Apply button uses the same guard when its profile contains main-story progress.
  5. Apply the planned jump as one undoable edit, export a test copy, then test it in-game with backups. Original input bytes remain untouched.

The preview evaluates all explicitly requested flags together. It shows exact changed bytes/masks, reserved/running/recently finished event banks, candidate conditions, partial script comparisons and omitted runtime work. Memories requires progress ≥440, its completion bit clear and six participant-enable queries; The Running Sign requires progress ≥139, its completion bit clear and nine queries. Unknown queries are not guessed as friendship checks. A failing known test means candidate eligibility is false; otherwise it remains unknown.

Stage 442 is observed beside Memories completion/cleanup; writing 442 does not perform that cleanup. Stage 511 is observed beside Ventuswill flags, schedules, tourist/point rewards and system bit 4; writing 511 does not run those actions. Mismatched observed flags and active events generate warnings, not automatic repairs. The separate system save and achievement-related runtime writer are untouched.

Profile scopes are main-story plus mapped barriers, town-event/request flags, or all named flags. All-flags profiles can also alter relationships, discovery, chests and unlocks. Only those flags are copied: NPC records, request payloads, location/party, inventory and reward history are not copied. Staged profiles can be downloaded for full review. Unknown symbols, invalid bounds and conflicting stages are rejected without partial application.

A universally playable checkpoint jump is not implemented. RSV/NOW alone do not initialize an event; AFTER is not completion history. Rewinding retains later state and advancing can omit prerequisites. Missing/mismatched imported evidence stays unknown, and script evidence comes from the audited PC build rather than proven Switch equivalence. See docs/story-jump-planner.md in the source tree for the detailed native/browser workflow and validation limits.

System saves

The supplied PC and Switch rf4_sys.sav containers share their size, signature and CRC layout. Slot calendar / bag / story controls are hidden for system files. Enable system editing for ending / extra-order, wedding-recorded and data-transfer flags. System bit 4 is only identified as a final-story-associated marker; its exact meaning is incomplete. Unknown bits and settings stay untouched unless edited through advanced offsets.

These flags do not complete a slot, replay an ending, grant rewards or unlock platform achievements. Sharing a container does not prove that every platform-specific setting is semantically interchangeable. System CRC is stored at bytes 4–7 and covers bytes 8–9303; the first eight bytes are protected.

Experimental PC / Switch conversion

Output defaults to the source platform. Choose PC or Switch in the output-format card and accept experimental conversion to create a new target-format file. The common body is retained; eight zero candidate-padding bytes are inserted before the PC trailer or removed for Switch. Removing nonzero bytes is blocked, the 224-byte trailer is preserved, and the target CRC is rebuilt.

The supplied slots pass byte-exact conversion-back checks. That is not an in-game acceptance test or proof of every unknown field’s platform layout. Keep backups and test exported copies. No console injection, account remapping, encryption handling or security bypass is provided. The shared system container has no length-conversion step.

Checksum and damage

Slot CRC-32 / IEEE is stored little-endian at offset 0 and covers bytes 4..140199 on PC or 4..140191 on the supplied Switch files. The final 224 slot bytes are outside CRC and preserved unless deliberately patched. System CRC uses its separate layout above. Export rebuilds CRC without modifying the held original. A mismatched original requires repair consent; repair does not recover damaged data.

Read-only item references

Venti’s data-table definitions are used only for reference lookups inside the save editor. There is no mod builder, TOML output, load-order manager, ZIP exporter, DLL installation or game-data writer. Venti does not need to be installed.

The four supported references are rf3ItemList.bin, rf3ItemEquipmentParam.bin, rf3UseItemParam.bin and rf3ItemStrengthening.bin. In the supplied game copy these contain 1,108 item definitions, 1,106 equipment records, 318 item-use records and 1,150 upgrade records. Each record size matched the C++ definition.

The item search uses the modkit’s vanilla name registry. Metadata read from your game copy is available automatically; Read tables can load extracted reference files instead. All inputs are read-only. Item prices mean item buy / sell values, not player money; equipment definitions are not the stats of a saved, upgraded item instance. Some definition tables cover only a subset of item IDs.

Copy ID to typed field prepares a draft only. It does not locate your bag or insert an item. You must separately provide an independently verified save offset, choose the correct integer width and explicitly apply the save edit.

Advanced save edits

Enable raw byte editing before using either the byte editor or typed field editor. Byte patches take space-separated two-digit hex values, up to 256 bytes per edit. Typed edits support signed or unsigned 8-, 16- and 32-bit integers stored little-endian. Bounds match the loaded file. Slot offsets 0–3 and system offsets 0–7 are protected.

The typed editor intentionally has no default inventory offset. Item IDs, category names and flag names are interpretation aids, not verified save mappings. Known category / flag names convert to integers, but the user remains responsible for the meaning and width at the selected offset. Any type of edit shares the same grouped undo / redo and save export.

For example, an unsigned 32-bit value of 9 is stored as 09 00 00 00. The hex preview highlights edited bytes; the JSON report shows changes against the original. Apply or clear draft fields before exporting.

Keyboard shortcuts

  • Ctrl+O: open a save.
  • Ctrl+S: export a real save.
  • Ctrl+Z: undo; Ctrl+Shift+Z or Ctrl+Y: redo outside text inputs.
  • Enter: apply a focused flag register.
